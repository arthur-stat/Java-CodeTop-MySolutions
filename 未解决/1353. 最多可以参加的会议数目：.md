题目简述：

> 给你一个数组 `events`，其中 `events[i] = [startDayi, endDayi]` ，表示会议 `i` 开始于 `startDayi` ，结束于 `endDayi` 。
>
> 你可以在满足 `startDayi <= d <= endDayi` 中的任意一天 `d` 参加会议 `i` 。在任意一天 `d` 中只能参加一场会议。
>
> 请你返回你可以参加的 **最大** 会议数目。

题目链接：[1353. 最多可以参加的会议数目](https://leetcode.cn/problems/maximum-number-of-events-that-can-be-attended/)

# 思路

原本我考虑的是普通区间排序，即优先按左端点升序排序、其次按右端点升序排序一次，然后对排序后的区间们进行静态地遍历，并且在该过程中使用贪心算法计数。在该逻辑下，我们尽可能地参加起始时间最早的会议，如果有多个会议起始时间相同，则优先参加截止时间最早的会议。就单调性而言，这样似乎能最大化利用时间。

> 事实上也的确如此，但前提是不存在起始时间相同的会议。下文会说明为什么当起始时间相同时，这一简单的逻辑会出问题。

但在编码并提交测试后，发现无法完全 AC。对于一些测试用例，比如 `[[1,2], [1,5], [2,2]]`，我的算法会出现问题。这种情况下，应当优先在第二天参加 `[2,2]` 的会议，但我们的算法会先在第一天参加 `[1,2]` 的会议、然后在第二天参加 `[1,5]` 的会议，于是就错过了 `[2,2]` 的会议。

通过这一简单的测试用例，我隐约意识到问题出在于我的区间排序只做了一次，是静态的，但我们参加了一场会议后，实际上剩余会议对于我们的最早可参加时间也发生了变化，这是一个动态的过程，需要想办法动态维护。

> 注：不可以按会议持续时间排序，然后实现优先参加会议时间最短会议的算法。因为那样的话会导致算法的复杂度和会议的起止时间有关，而且也不好实现。不过，在分析简单例子时，可以按这个思路进行分析。

如何理解所谓「动态维护」呢？比如，还是 `[[1,2], [1,5], [2,2]]` 的例子，我们参加完第一天会议后，剩余的会议是 `[[1,5], [2,2]]`。但要知道，在第一天参加了会议 `[1,2]` 后，我们下次可参加会议的时间已经来到了第二天，尽管 `[[1,5], [2,2]]` 符合「优先按左端点升序排序、其次按右端点升序排序」的区间排序逻辑，可是此时我们已经不可能回到第一天同时参加会议 `[1,5]` 了，因此左端点的 `1` 实际上是一个无效值，我们应该把会议 `[1,5]` 更新为 `[2,5]`，让 `[2,5]` 与 `[2,2]`「同台竞争」。显然，按照我们的区间排序逻辑，这时应当首先参加 `[2,2]`——很好，这就对了！

但是我们不可能每参加一个会议就更新所有会议的起始时间，然后再重新做一次排序，这样做代价太大。于是我的思路就卡在这里了，我没有想出来如何简洁高效地实现「动态维护」的逻辑。我陷了进去。

下面是按上述思路实现的错误代码：

```java
class Solution {
    public int maxEvents(int[][] events) {
        Arrays.sort(events, (a, b) -> {
            if (Integer.compare(a[0], b[0]) != 0) return Integer.compare(a[0], b[0]);
            return Integer.compare(a[1], b[1]);
        });

        int count = 0;
        int d = 0;  // 下一次可参加会议的最早时间
        for (int[] event : events) {
            if (d <= event[1]) {
                d = Math.max(d, event[0]) + 1;
                count++;
            }
        }

        return count;
    }
}
```

---

事实上，要实现「动态」，我们要做的只是跳出只做一次全局排序的经典区间排序问题的定式思维——考虑优先队列（最小堆、小顶堆）即可！对呀，我当时怎么没想到优先队列呢？这一数据结构正是用以动态维护最值的数据结构。

当然，知道了用优先队列后，怎么把优先队列用对，也是个问题。依然考虑对区间们首先按「优先按左端点升序排序、其次按右端点升序排序」的逻辑排序，但接着，我们在遍历的过程中用优先队列维护当前可参加的会议们。

具体做法是：在遍历过程中，假设下一次可参加会议的最早日期是第 `d` 天，那么就把所有起始时间在 `d` 及其以前且终止时间在 `d` 及其以后的会议加入到队列中，弹出终止时间最小
